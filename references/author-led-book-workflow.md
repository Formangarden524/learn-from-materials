# 作者主线单书拆解

用于“拆一本书／把整本书做成可视化交互网页”。目标是理解并保留这位作者在这本书中怎样提出问题、组织概念、展开论证、使用案例与设置边界。最终交付可追溯的全书内容档案与同源网页，供之后的主题 Wiki 选择性复用。用户只要样板或导读时采用 `guided-reading-workflow.md`；明确 quick／systematic 时优先执行其既有契约。

这条路线改变生产顺序与呈现方式，保留全书拆解目标。不要把“早出样板”误作“只交摘要”，也不为一个单书档案重建完整主题知识体系。

本版新装配器要求 PDF 页级来源映射。EPUB、Word 等格式继续使用原有 quick/systematic 交付路线；不将缺失定位伪装为 PDF 页。

## 1. 先复用，再补读

只检查用户指定书与工作目录。先核对原书指纹、来源映射、原目录、规范单元和已有复核记录。原文未变时不重复提取或 OCR，不从成品网页倒推事实。已有稳定 ID、原文定位、作者身份、解释和有效核查应保留。

优先复用规范内容源；Markdown、页面 JSON、HTML 作为派生成果核对。旧成果有冲突时查清实际拥有该内容的记录，不凭“文件更新较晚”决定真伪。源文件、映射或内容变动时只复查相应依赖。机械迁移记录输入与输出指纹、原 ID 到导出 ID 的映射及缺口，不授予新语义审核状态。

没有可复用单元的新书，先完成可靠提取与完整结构扫描，核对目录、开头、收束及主要部分的代表正文，再进入主线判断。结构扫描不等于逐页精读；关键图表、未读和不可读范围分别保留。

## 2. 以作者的骨架做主线样板

识别作者的中心问题、主要主张、明确提出的模型／分类，以及章节如何展开、补充、比较或限制这些主张。保留原章名与顺序供对照；总模型、子机制、条件、案例与查阅资料各有层级。没有来源支持的行动顺序或因果关系不画成作者流程。

作者明确命名的框架、连续原文、忠实转述与编辑新增的分组分别标示。将若干章节归为几个阅读区，是编辑归纳；即使忠实于章节顺序，也不能称为作者原有的分区名称。实际作者、引文作者、病例叙述者和编辑手记不混同。结构服从材料，不固定黄金圈、节点数、步骤数或某个专业模型。

先渲染一屏能看清的作者主线与能检验解释深度的代表章节。默认层讲清“是什么、为什么、在本书中起什么作用”；重要区别、条件与材料已有例子完整保留，更多细节按需展开。样板本身沿用后续档案的单元 ID 与来源。

用户要求先确认时，交付具体样板并等待主线和代表章节的反馈。会话已有明确确认或用户授权连续完成时直接继续；不重复询问已经批准的范围。只认可页面布局，不自动等于确认新增加的作者主线；有实质结构变更时如实标明待确认部分。已有完整内容可以先机械归档供核对，其复用状态与主线确认状态分开记录。

## 3. 确认后完成全书档案

新完整单书按 `book-context-workflow.md` 初始化独立接续状态，原文分包阅读、稳定单元落盘并分别记录章节回读和查漏。已有规范成果只登记真实复用范围，不能自动把覆盖标记转成已读。接续减少重复上下文，不减少全书完整性要求。

按原书顺序逐章补齐原文，保留独立主张、关键概念、作者模型、论证联系、案例的经过与解释、适用条件、反例及限制。序言、附录、结语和编辑手记有实质内容时纳入，并保留其不同身份；不以“不是正文章节”排除。

一个章节可以拆为多个学习单元，一个概念可以跨章扩展。保留必要原 ID 与首次出现、后续扩展来源，不按页面卡片数量删减独立内容，也不把全书只压成几个导读节点。没有案例或行动方法时如实省略，不为模板补造。相同观点只在确实等价时合并，差异、矛盾和无法核验之处保留。

内容档案至少能定位到：这本书及作者、原章节、稳定单元、实际来源范围、该单元的主张／解释／案例／条件、已有审核身份与具体缺口。沿用现有规范记录即可；不为字段命名重新抄写全书，不建立重复账本。新内容及时保存，摘要和网页从同一份内容源生成。

全书是否完成取决于约定材料范围、独立内容与缺口核对。脚本通过、章节都有一段摘要或单位数量增加，均不单独证明完整。旧记录只继承其原有、可匹配的复核证据；本次新写、重组或改变的解释与关系仍需核对相应原文。原文经验、传统理论、作者推断和外部验证保持不同证据身份。

### 新书的轻量单元记录

已有 `unit-record-v2` 原样复用。新书可用 `schemaVersion: learn-from-materials/book-unit-v1`，不为满足旧 v2 扩写候选和多份账本。每单元保存：

- `unit`：`id/label/title/source/core/takeaways/conclusions`；`core` 与每条 takeaway 为 `{id,text}`，每组 conclusion 为 `{title,source,summary:{id,text},points:[{id,text}]}`。ID 稳定，内容按原书展开。
- `sources`：`[{sourceId,status,reason}]`，如实标记已覆盖、未读或不可读范围；`claims`：`[{id,kind,text,source,sourceIds,contentIds,evidence}]`，把实际显示内容关联到真实来源与证据。
- `sections/frameworks/glossary/decisionRules` 可选，只在材料实际具备且本单元需要时写；不创建空项凑格式。`review` 记录真实阅读范围、人员、状态与限制，不使用脚本自动生成的语义批准。

构建器只迁移内容、校验引用和派生输出，不授予语义完成状态。这个轻量约定不冒充完整 v2，也不要求另建全量 relation／summary 账本；必要核查仍针对所写解释与原文的支持关系。

## 4. 同源网页与 Wiki 复用包

复用轻量模板 `templates/author-book.html`，由 `scripts/build_book_archive.py` 读取已有知识库与明确的作者主线映射：

```text
python3 scripts/build_book_archive.py --knowledge-base KB --structure author-structure.json --output-dir DELIVERY
```

该工具机械派生可浏览档案、交互网页与复用数据；不自动编写新主张，不为旧内容生成“本次语义已审”标志。具体文件清单及输入格式以工具实际帮助和输出清单为准，不在交付前凭空声明成功。

网页先呈现作者主线，再沿原章节／单元展开；可查看原目录、核心解释、细节和来源。页面不以主题 Wiki 的分类替换原书结构。来源、作者观点、忠实转述与编辑结构继续使用清楚的文字标签，原始数据与网页保持一致。

Wiki 复用数据保留稳定的 `bookId/unitId/conceptId`（缺少时由来源指纹和已有 ID 派生并保留映射）、作者身份、原章及来源定位、原书观点和证据类别。它提供可引用的单书内容，不预先把同名概念合并成跨书定论；候选关联标为候选。未经用户指定目标与授权，不自动写入主题 Wiki、改写其已有页面或执行跨书综合。

## 5. 验证与交付

先验证主线与代表章节，再检查新增内容及实际受影响的交互。每次交付核对全书章序、规范单元是否全部保留、单元和来源 ID 是否稳定、出处入口、引用与实际段落支持关系，以及缺口和复核状态是否如实。关键图表以已有有效记录复用或实际查看，不能仅凭空文本判断没有信息。

用现有全书成果验证时，记录迁移复用数量与来源范围，检查档案、网页和 Wiki 复用数据的内容一致性；不重新拆整本书来证明程序能运行。桌面、窄屏与长内容的可读性、搜索／切换／展开／出处交互按本次实际界面检查。没有运行的检查明确保留未运行。

最终链接交互网页、内容档案与 Wiki 复用包，并说明主线确认状态、完整性与本次核验范围。单书档案完成不冒充旧 systematic 门禁；用户后来选择旧 systematic 时复用有效成果，再补齐其契约。按提取／结构样板／扩展／复核／界面修订分开计时，不将旧底库复用速度当作新书全流程速度。

已有认可的代表讲解可用 `--representative-reading CONTENT.json` 复用导读内容源。构建器仅提取代表单元的讲解分组与引用，不带入旧导读的全书分组；逐条核对原文、上下文、页码与引用ID，原规范单元保持原样。网页先呈现样板讲解，再允许展开完整单元档案。当前内置模板固定标签为中文，其他语言需另存翻译模板并说明范围。


## 首页原书封面

书籍网页默认在首页标题旁展示可靠的原书封面。先实际查看上传PDF封面页或用户提供的图片，确认是本书封面；不得仅因是PDF第1页就直接认定，也不联网找图或生成替代封面。没有可确认封面时省略，保持原布局，不中断正文生成。

从已提取图片复用，或将已确认的封面页渲染为本地PNG/JPEG/WebP。构建作者主线网页与导读时可传 `--cover-image /path/to/cover.png --cover-page 1`；页码必须是实际物理PDF页，非PDF图片省略页码。图片以data URL嵌入，不依赖远程加载，保持完整比例，窄屏缩小。`meta.cover`为可选展示字段，包含`dataUrl/sha256/alt/sourcePage/sourceLabel`，不改变书籍、章节、单元、主张及来源ID。旧内容无此字段仍正常渲染。

纯封面更新复用正文与来源，不重新拆解书籍；检查桌面/窄屏封面、主线、出处与无封面回退。封面是书籍身份展示，不是为内容新增证据或语义审核。

## 通用逐章路线与统一交付入口

确认后补齐原章的阅读问题、关键概念和前后衔接，作为编辑归纳显示；不改原书次序和单元ID。使用 `scripts/book_pipeline.py` 统一生成、核验和公开派生，有部署授权时完成上线读回；字段、配置、浏览器证据与续跑约定见 `book-pipeline-workflow.md`。

原书由文章、讲次等组成时，可在结构中设置 `chapterNoun`（默认“章”）及每行 `chapterLabel`，保留真实单位和索引身份。轻量单元没有细节条目、要点或框架时，模板省略相应空展开控件。转述中夹有明确的导读辨析时，主张使用 `kind: paraphrase-and-commentary`，页面显示“导读展开 · 转述与辨析”。
